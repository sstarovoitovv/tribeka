# ТРИБЕКА

Корпоративный сайт металлообрабатывающей компании: каталог 11 услуг, возможности оборудования, контакты и заявка с чертежами.

**Основной сайт:** [трибека.рф](https://трибека.рф/).

React собирается в готовые HTML-страницы. Форму обрабатывает PHP на REG.RU: проверяет данные и вложения, сохраняет заявку в MySQL и отправляет уведомление. Статистика пользователей не собирается.

## Стек

| Часть | Технологии |
| --- | --- |
| Интерфейс | React 18, React Router 7, Manrope |
| Стили | Tailwind CSS 3 |
| Сборка | Vite 6, статическая генерация HTML |
| Заявки | PHP 8.3, MySQL |
| Проверки | Vitest, Playwright, PHP, Apache |
| Публикация | GitHub Actions → REG.RU, резервная копия и атомарное переключение релиза |

## Структура

```text
src/
  pages/               # Страницы сайта
  components/          # Общие элементы и форма
  data/company.js      # Услуги: адреса, тексты, параметры, фотографии и лицензии
  siteConfig.js        # Контакты, логотип, адрес API
  seoConfig.js         # Метаданные и правила индексации
public/
  images/services/     # Фотографии услуг в WebP
  brand/               # Логотип и материалы компании
  api/                 # PHP-обработчик и проверка входящих данных
server/                # Резервное копирование, деплой, очистка данных
scripts/               # Генерация HTML, локальный просмотр и HTTP-проверки
tests/                # PHP- и браузерные тесты
database/migrations/  # Схема базы заявок
docs/                 # Инструкции по эксплуатации
.github/workflows/     # Автоматические проверки и публикация
```

Frontend-тесты находятся рядом с проверяемым кодом в `src/`. `dist/`, `node_modules/` и `.work/` — локальные результаты сборки, зависимости и временные материалы; в Git они не входят.

## Локальный запуск

Нужен Node.js 20+.

```bash
npm ci
npm run dev
```

Для локальной работы создайте `.env.local`:

```dotenv
VITE_FORM_ENDPOINT=/api/request.php
```

Это не отправляет локальные заявки на основной сайт. Vite и сервер предпросмотра не исполняют PHP; обработчик проверяется отдельными PHP-тестами.

Просмотр собранного сайта с настоящими HTML-страницами и HTTP 404:

```bash
npm run build
npm run preview:production
```

Адрес: `http://127.0.0.1:4173`. Другой порт: `PORT=4179 npm run preview:production`.

## Где менять содержимое

- **Услуги и фотографии:** `src/data/company.js`. Каждая услуга содержит собственный объект `image`; каталог и подробная страница используют одну фотографию. При перестановке карточек сохраняйте `number`: из него получаются постоянные `id` и `slug`. При смене URL задайте `slug` и старые адреса в `aliases` явно.
- **Контакты и логотип:** `src/siteConfig.js`.
- **Страницы:** `src/pages/`; общие элементы — `src/components/`.
- **Цвета и оформление:** `tailwind.config.js` и `src/index.css`.
- **SEO:** `src/seoConfig.js`. Страницы услуг пока имеют `noindex`, поскольку примеры работ остаются заглушками. Порядок изменения URL и индексации — в [инструкции](docs/ssg-seo.md).

Фотографии иллюстрируют направления работ. Источники и лицензии указаны [отдельно](docs/service-photo-sources.md) и доступны в каталоге. Заглушки портфолио заменяются только реальными материалами.

## Проверки

```bash
npm run lint
npm test
npm run build
npm run test:ssg
npx playwright install chromium
npm run test:e2e
```

Серверные проверки требуют PHP 8.3 с `mbstring`, `fileinfo`, `pdo_mysql`, `pdo_sqlite`, `zip`, а также `tar`:

```bash
npm run test:php
npm run test:deploy
```

Полный набор, включая Apache, запускается в GitHub Actions. Тесты используют изолированные данные и не отправляют реальные заявки.

## Публикация

1. Разработка — в отдельной ветке; `develop` хранит согласованное состояние разработки.
2. Pull request в `main` запускает проверки.
3. После объединения GitHub Actions проверяет сборку, загружает отдельный релиз на REG.RU и создаёт резервную копию данных.
4. Сайт атомарно переключается на новый релиз. При ошибке HTTP-проверки автоматически возвращается предыдущий код.

Основной сайт не зависит от Vercel. Секрет `REG_RU_SSH_KEY` хранится в GitHub Actions. Серверный `config.php`, пароли и вложения находятся вне публичного каталога и не входят в репозиторий. Пример конфигурации: `server/config.example.php`.
