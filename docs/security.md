# Серверная защита и границы проверки

`public/api/_lib/request-security.php` не содержит секретов. Прямой HTTP-доступ к библиотеке закрыт PHP и Apache; Vercel исключает весь PHP. Закрытый config читается по постоянному пути или TRIBEKA_PRIVATE_CONFIG; схема размещения релизов его не меняет.

- Имя/телефон/сообщение проверяются на PHP: строковые типы, UTF-8, ограничения длины, управляющие символы, формат международного телефона. Для +7 дополнительно проверяется структура RU/KZ. Клиент использует полные метаданные libphonenumber; PHP не проверяет существование номера или владельца.
- Согласие должно быть именно `privacy=on`; наличие ключа или `false` не считается согласием. Версии документов должны совпадать с опубликованными. Источник формы ограничен разрешённым origin, query/hash не сохраняются.
- CORS допускает apex/www и только явно указанные origins. Все сайты `*.vercel.app` и произвольный localhost больше не доверенные по умолчанию. Прямой HTTP-клиент может подделать Origin, поэтому CORS дополняется самостоятельной валидацией и rate limit.
- `attachments[]` сохраняет несколько файлов. PHP проверяет форму multipart-массива, фактический файл из HTTP-upload, реальный размер, расширение, MIME и сигнатуры CAD/PDF/изображений/архивов. Лимит 5 файлов и 15 МБ суммарно. PHP получает до 20 файлов, чтобы шестой был явно отвергнут приложением; иначе max_file_uploads=5 молча отбросил бы лишние.
- Файлы имеют случайные имена, права 600 и каталог 700 вне webroot. Не распаковываются сервером и не имеют публичного URL. SHA-256 сохраняется в реестре. При ошибке записи в БД созданные файлы удаляются.
- Проверка MIME/сигнатур не является антивирусом и не гарантирует отсутствие вредоносного содержимого внутри подлинного PDF/CAD/архива. Антивирусный сервис на REG.RU не подключён. Для сканирования перед обработкой нужно выделить доступный scanner/карантин; сотрудникам следует открывать присланные документы в защищённой среде.
- Rate limit резервируется **до** проверки заявки атомарно под flock. Проверка+запись не разделены. Один адрес — одна попытка раз в 30 секунд, ответ 429 и Retry-After. Стабильные shard-файлы не удаляются во время работы, число записей ограничено; ошибка состояния закрывает приём, а не отключает защиту.
- Используется REMOTE_ADDR, а не переданный клиентом X-Forwarded-For. В цепочке nginx → Apache хостинг должен корректно устанавливать реальный клиентский IP только от доверенного proxy. Иначе все клиенты за адресом proxy будут делить лимит; проверить это при первом релизе.
- Формы и очистители держат shared maintenance lock, backup — exclusive. Во время snapshot новая заявка получает понятный 503; пользовательские поля остаются заполненными. Удалённый SQL и вложения должны восстанавливаться из одной копии.

Автотесты не отправляют реальные письма и не записывают production-лиды. 82 проверки PHP включают реальные HTTP multipart запросы, подделку формата, вложенные поля, повторные обращения, конкурентную гонку 16 процессов и очистку файлов при ошибке БД. Отдельные проверки аналитики работают с настоящим HTTP endpoint и изолированным файловым хранилищем. Deployment-тесты проверяют lock/архивы/checksum/откат; mysqldump там подменён fixture. Проверка восстановления настоящего MySQL и vhost/FPM REG.RU остаётся этапом приёмки сервера.
